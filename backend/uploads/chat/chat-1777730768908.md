# Goal Description

Implement a professional real-time multimedia messaging and chatbot system for the logistics platform. The system will handle secure, role-restricted communication across 4 roles (Client, Chauffeur, Responsable, Admin) and support text, image, file, and voice messages with real-time updates via Socket.io. It also includes an automated chatbot workflow for Client ↔ Responsable support that escalates complex queries.

## Proposed Changes

### Backend (Node.js + Express + MongoDB)

#### [NEW] `backend/models/Conversation.js`
- **Schema:** 
  - `participants`: Array of ObjectIds ref `Utilisateur`
  - `type`: Enum `["support", "delivery", "driver", "admin"]`
  - `lastMessage`: ObjectId ref `Message`
  - `unreadCounts`: Map of String (userId) to Number
- **Purpose:** Track multiple chat threads between users.

#### [NEW] `backend/models/Message.js`
- **Schema:**
  - `conversationId`: ObjectId ref `Conversation`
  - `senderId`: ObjectId ref `Utilisateur` (can be null for bot)
  - `messageType`: Enum `["text", "image", "file", "audio"]`
  - `content`: String (text or file URL)
  - `fileName`, `fileSize`, `mimeType`, `duration` (optional fields based on type)
  - `readBy`: Array of ObjectIds
  - `isBot`: Boolean
  - `isEscalated`: Boolean
- **Purpose:** Store rich multimedia messages.

#### [NEW] `backend/controllers/chat.controller.js` & `backend/routes/chat.routes.js`
- **Endpoints:**
  - `POST /api/chat/conversation`: Create a conversation (with role-based security validation).
  - `GET /api/chat/conversations/:userId`: Fetch user's inbox.
  - `GET /api/chat/messages/:conversationId`: Fetch paginated messages.
  - `POST /api/chat/message`: Send a message (triggers socket events and handles chatbot escalation logic if type is "support").
  - `PUT /api/chat/message/read`: Update seen status.

#### [NEW] `backend/controllers/upload.controller.js` & `backend/routes/upload.routes.js`
- **Endpoints:** `POST /api/upload`
- **Purpose:** Integrated with `multer` and Cloudinary API to handle parsing and uploading images, files, and audio blobs.

#### [NEW] `backend/sockets/chat.socket.js`
- **Events:**
  - `join_conversation`, `leave_conversation`
  - `send_message`, `receive_message`
  - `typing`, `stop_typing`
  - `message_seen`
- **Integration:** Hooked into `Server.js` to initialize `socket.io`.

### Security Constraints implementation
- Middleware in `chat.controller.js` will strictly enforce:
  - Client ↔ Responsable
  - Responsable ↔ Chauffeur
  - Chauffeur ↔ Chauffeur
  - Admin ↔ Responsable

### Frontend (React)

#### [NEW] `frontend/src/chat/context/ChatContext.jsx`
- Manages Socket.io connection, active conversation state, and global unread badges.

#### [NEW] `frontend/src/chat/components/ChatSidebar.jsx`
- Displays the list of multiple conversations.
- Shows latest message snippet, timestamp, and unread badges.

#### [NEW] `frontend/src/chat/components/ChatWindow.jsx`
- Main message viewing area.
- Supports lazy loading/pagination.
- Renders specific UI based on `messageType`:
  - Image previews
  - Clickable file icons (PDF/DOCX)
  - Audio player for voice messages
- Message status indicators (sent, delivered, seen ticks).

#### [NEW] `frontend/src/chat/components/ChatInput.jsx`
- Input box for typing text.
- Integrated file input for attachments.
- **Voice Recorder:** Implementation using the browser's `MediaRecorder` API to capture microphone input, build a Blob, and upload via the `POST /api/upload` route.

#### [NEW] `frontend/src/services/chatService.js` & `uploadService.js`
- Axios wrappers for the new backend routes.

- **Role Validation:** Attempt to create unauthorized conversation types (e.g., Client ↔ Chauffeur) to ensure the API blocks it.
- **File Upload:** Upload an image, a document, and a recorded audio message to ensure Cloudinary returns valid secure URLs.
- **Chatbot Workflow:** Simulate a Client sending a "support" message. Verify the system triggers the bot response and correctly flags `isEscalated` if confidence is low.
- **Real-Time Sockets:** Open the app in two separate browsers (e.g., Responsable and Chauffeur). Verify typing indicators appear instantly, and sent messages display the double-tick "seen" status when viewed.
